NorthStar Retail: how the project works, how to run it, how to explain it

One page that covers the whole project from start to finish, written in simple English. Read it top to bottom once, then use the contents list to jump back to any part.

Project on GitHub: github.com/PrabhasMaringanti-20/uk-retail-sales-bi-dashboard

What the project is

In one sentence: a pretend UK shop chain is selling more every year but not making more profit, and this project finds out why and what the managers should do about it.

The shop is called NorthStar Retail UK. It is not a real company. All the data was created by a computer program so that it behaves like a real shop: busy Christmases, January sales, growing online orders, a shoe brand with sizing problems. Always say this openly in interviews.

The business problem

The managers get four different weekly reports (stores, website, finance, returns) and the numbers don't agree. Sales are going up, but nobody can say where the profit is being lost. The project builds one trusted set of numbers and a dashboard that answers: what is happening, why, where, and what to do.

What we found

+15.7%sales growth, 2024 → 2025
(£3.96M → £4.58M)
+9.4%profit growth only
43.3% → 41.0%profit per £1 of sales fell 2.4p
19% vs 6%Electronics: share of sales vs share of profit
  • Too many discounts: discounts of 30% or more leave almost no profit. Electronics loses money on any discount above about 19%.
  • Costs rose faster than prices: suppliers charged about 6% more, the shop raised prices only about 3%.
  • Returns are rising online: online clothes and shoes returns went from about 16% to about 27%, mostly one shoe brand (Stride Lab) whose sizes are wrong.
  • Two stores discount far too much: Newcastle gives three times more discount than the other stores.
  • Loyal customers matter: 14% of customers bring in half the sales, and 1,450 of the loyal ones have stopped buying.

What it is used for (why employers care)

Real companies hire Data Analysts and BI Analysts to do exactly this: take messy data, clean it, put it in a database, build a dashboard, and turn numbers into decisions. This project shows your brother can do every one of those steps, with the same tools UK job adverts ask for: SQL, Power BI, DAX and Excel.

The star schema in simple words: think of a till receipt. The numbers (quantity, price, profit) go in the middle table called FactSales. The descriptions (product name, store city, customer type, month) go in smaller tables around it called DimProduct, DimStore, DimCustomer, DimDate. Drawn on paper, it looks like a star.

A taste of each kind of code (what it does, in simple words)

Python cleaning rule: the same channel was typed 14 different ways. This maps them all to 4 standard names.

scripts/03_clean_data.py 
CHANNEL_MAP = {"in-store": "In-Store", "instore": "In-Store", "store": "In-Store",
               "website": "Website",   "web": "Website",
               "mobile app": "Mobile App", "app": "Mobile App",
               "click & collect": "Click & Collect", "c&c": "Click & Collect"}
s["Channel"] = s["Channel"].str.lower().map(CHANNEL_MAP)   # "WEB" -> "web" -> "Website"

SQL question: "How much did each category sell, and how much profit did it make?"

sql/04_business_questions.sql (Q03, simplified) 
SELECT p.category,
       SUM(s.net_sales)                        AS revenue,
       SUM(s.gross_profit) / SUM(s.net_sales)  AS margin
FROM   fact_sales s
JOIN   dim_product p ON p.product_key = s.product_key   -- bring in the category name
GROUP  BY p.category                                    -- one row per category
ORDER  BY revenue DESC;

DAX formula (Power BI): profit as a percentage of sales, and sales compared with last year.

dax/measures.dax 
Gross Margin % = DIVIDE ( [Gross Profit], [Revenue] )
Revenue PY     = CALCULATE ( [Revenue], SAMEPERIODLASTYEAR ( DimDate[Date] ) )
Revenue YoY %  = DIVIDE ( [Revenue] - [Revenue PY], [Revenue PY] )

How to run it on a laptop (yours or your brother's)

There are four levels. Do them in order. Level 1 and 2 are enough to see everything working.

See the results

Download and open the slides, Excel and pictures. Nothing to install.

Level 2 · 30 min

Open the dashboard

Install Power BI Desktop and load the data. Windows only.

Level 3 · 1 hour

Run the SQL

Install PostgreSQL and run the 40 questions yourself.

Level 4 · 1 hour

Run the Python

Re-create all the data and files from scratch.

Level 1: get the project and see the results

  1. DownloadOpen the GitHub link → green Code button → Download ZIP.
  2. Unzip to a simple placeRight-click the ZIP → Extract All. Put it at C:\NorthStar\ so you get C:\NorthStar\uk-retail-sales-bi-dashboard\.
  3. Unzip the dataOpen data → right-click clean_data.zip → Extract All → extract here, into the data folder. You should now have data\clean\fact_sales.csv.
  4. Look at the resultsOpen presentation\NorthStar_Executive_Presentation.pptx first, then excel\NorthStar_Excel_Analysis.xlsx, then the screenshots folder.

Level 2: open the Power BI dashboard

  1. Install Power BI DesktopFree from the Microsoft Store. If it asks you to sign in, close the window. You don't need an account (a Gmail address is not accepted, and that's fine).
  2. Open the dashboardDouble-click powerbi\NorthStar_Retail_Dashboard.pbip. The pages appear but the boxes say "(Blank)". That's normal: the data isn't loaded yet.
  3. Tell Power BI where the data isHome → arrow under Transform data → Edit parameters → DataFolder. Type the exact path of your clean folder, ending with \. Example: C:\NorthStar\uk-retail-sales-bi-dashboard\data\clean\
  4. Load the dataClick Apply changes (or Refresh). Wait about a minute.
  5. Check it's rightOn page 1 the year table must show £3,961,750 for 2024 and £4,584,138 for 2025. If it matches, everything works.
How to find the exact path of the data folder: open File Explorer, search for fact_sales.csv, right-click it → Open file location, then click the address bar at the top and copy the text. On your laptop it was on the D: drive: D:\Northstar\uk-retail-sales-bi-dashboard\data\clean\. No quotation marks, and keep the \ at the end.

Level 3: run the SQL yourself

  1. Install PostgreSQLDownload from postgresql.org. The installer includes pgAdmin. Remember the password you choose.
  2. Create the databaseOpen pgAdmin → right-click Databases → Create → Database → name it northstar.
  3. Create the tablesRight-click northstar → Query Tool → open sql\01_create_schema.sql → press F5 (run).
  4. Load the dataIn the left tree open northstar → Schemas → northstar → Tables. For each table: right-click → Import/Export Data → Import → pick the matching CSV from data\clean\ → turn Header on → OK. Load in this order: dim_date, dim_customer, dim_product, dim_region, dim_store, dim_channel, then fact_sales, then fact_returns.
  5. Run the checks and the 40 questionsOpen and run sql\03_data_quality_checks.sql (all should say PASS), then sql\04_business_questions.sql. Compare your answers with sql\README.md, which explains every query.

  2. Open a terminal in the projectOpen the project folder in VS Code → Terminal → New Terminal.

How to explain it to others

To family or friends (non-technical)

"I built a system for a pretend shop chain that sells more every year but doesn't make more money. It collects all their sales, fixes the mistakes in the data, and shows on one screen where money is made and lost. It showed they give away too much in discounts, electronics barely make money, and one brand of shoes keeps getting sent back because the sizes are wrong."

In an interview: 30 seconds

"I built an end-to-end retail analytics project for a simulated UK retailer. I generated two years of realistic data, cleaned it with 40 documented rules, built a star schema in PostgreSQL, answered 40 business questions in SQL, and built a 5-page Power BI dashboard with DAX. The main finding was that revenue grew 15.7% but profit only 9.4%, because of discounting and weak Electronics margins. I turned that into prioritised recommendations."

In an interview: 2 minutes (Situation → Task → Action → Result)

  • Situation: a simulated UK retailer had four reports that disagreed. Sales were up but nobody knew where profit was lost.
  • Task: build one trusted source of numbers and explain what's happening, why, and what to do.
  • Action: defined the KPIs first; created realistic data and added real-world mess; cleaned it with 40 rules (fix if certain, flag if unsure, set aside if untrustworthy); built a star schema in PostgreSQL with built-in rules; wrote 40 SQL analyses; built the Power BI dashboard with 52 DAX measures; checked that SQL, Excel and Power BI all give the same totals.
  • Result: profit per £1 fell 2.4p (1.6p from costs not passed on, 0.8p from more discounts); Electronics loses money above a ~19% discount; one shoe supplier tripled its returns. Recommended category discount limits, supplier action and a win-back campaign, ranked on an impact vs effort chart.
Always say this honestly: "It's a simulated project with synthetic data, so it shows my skills, not real work experience, and the money figures are estimates with stated assumptions." Interviewers respect honesty. Never claim it was a real company or that it saved real money.

Questions interviewers will ask (with answers)

Practise out loud. Use your own words; memorised answers sound memorised. The full list of 50 questions is in notes/14_interview_question_bank.md.

Is this real company data?

No. It's a simulated UK retailer with synthetic data I generated, with realistic patterns built in. The methods are exactly what I'd use on real data.

Walk me through your project.

Use the 2-minute answer above: problem → data → cleaning → database → SQL → dashboard → findings → recommendations.

Why did you use a star schema?

Each description is stored once instead of repeated on 185,000 rows. It's simple for users (filter by descriptions, add up the numbers) and it's what Power BI is built to work fastest with.

What is the "grain" of your sales table?

One row per order line: one product within one order. Orders are counted with a distinct count of the order number, not by counting rows.

What's the difference between WHERE and HAVING?

WHERE filters rows before grouping. HAVING filters groups after the totals are calculated.

How did you calculate year-over-year growth?

In SQL: monthly totals in a CTE, then LAG(revenue, 12) to get the same month last year. In DAX: CALCULATE([Revenue], SAMEPERIODLASTYEAR(DimDate[Date])), then divide.

What does CALCULATE do in DAX?

It calculates a measure with changed filters. For example, Customers = distinct customers, but with the anonymous "Guest" customers filtered out.

Tell me about a data quality problem you solved.

Sales came with 14 different spellings of 4 channels, two date formats and a batch loaded twice. I used a mapping table, explicit date formats and duplicate removal. Validity went from 92% to 100%, only 0.05% of rows were set aside, and the cleaned revenue matched exactly.

Blank customer IDs: did you delete them?

No. Blank means the shopper didn't scan a loyalty card in store. That's legitimate, worth £1.36M of sales. I kept them as a "Guest" customer instead of deleting real revenue.

How did you make sure your numbers were correct?

One reconciliation total that every tool must match (£8,545,888 revenue), 13 automatic PASS/FAIL checks in the database, and comparing SQL, Excel and Power BI side by side.

What was your most important insight?

Profit grew much slower than sales. I split the 2.4-point margin drop into costs rising faster than prices (1.6) and more discounting (0.8), which moved the conversation from "sell more" to "protect margin".

The CEO wants 30% off everything on Black Friday. What do you say?

Electronics breaks even at about 19% off, so 30% off loses money on every electronics sale. I'd suggest different discount limits per category and test them in a few regions first.

How did you use AI in this project?

Be honest: "I used AI as a mentor and coding assistant, like a senior colleague. I ran everything, checked every number against the database, and I can explain every decision." Then prove it by explaining any file they point at.

What would you do differently or add next?

Add stock/inventory data, schedule automatic refreshes, publish the dashboard online, and test a discount change with a proper A/B test.
