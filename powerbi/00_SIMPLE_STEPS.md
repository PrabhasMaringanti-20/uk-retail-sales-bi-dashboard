# Power BI: Simple Step-by-Step

There are two ways to get the dashboard. **Do Way 1 first** to see the finished result, then **do Way 2 yourself** to
learn it. Interviewers will ask you to explain how you built it.

You need a **Windows** computer with **Power BI Desktop**: free from the Microsoft Store, or search "Power BI Desktop download".

---

## Before you start: get the data (5 minutes)

1. Download this repository (green **Code** button → **Download ZIP**) and unzip it to
   `C:\NorthStar\uk-retail-sales-bi-dashboard\`
2. Inside it, unzip `data\clean_data.zip`. You should now have the CSVs in:
   `C:\NorthStar\uk-retail-sales-bi-dashboard\data\clean\` (`fact_sales.csv`, `dim_date.csv` …)

> If you put the folder somewhere else, that's fine. You'll just change one setting (the `DataFolder` parameter) in step 3 below.

---

## WAY 1: Open the ready-made dashboard (10 minutes)

The project already contains a complete Power BI Project: 8 tables, 13 relationships, 52 DAX measures and 5 pages
with 76 visuals, generated by `scripts/helpers/build_powerbi_project.py`.

1. Open `powerbi\NorthStar_Retail_Dashboard.pbip` (double-click it, or Power BI Desktop → **File → Open**).
   - If it won't open: **File → Options and settings → Options → Preview features** → tick
     **"Power BI Project (.pbip) save option"** → restart Power BI Desktop. (Newer versions don't need this.)
2. You'll see the pages but **empty visuals**. That's normal, because the data hasn't been loaded yet.
3. If your folder isn't `C:\NorthStar\uk-retail-sales-bi-dashboard\data\clean\`:
   **Home → Transform data (arrow) → Edit parameters** → set `DataFolder` to your `...\data\clean\` path
   (**end it with a `\`**) → OK.
4. Click **Home → Refresh**. It takes 20–60 seconds to load about 186,000 rows.
5. **Check the numbers:** on the *Executive Overview* page, the year table should show
   2024 revenue **£3,961,750**, 2025 **£4,584,138**, total **£8,545,888**. If it matches, the model is correct. 🎉
6. Optional: **View → Themes → Browse for themes** → `powerbi\northstar_theme.json` for the project colours.
7. **File → Save as** → choose **.pbix** if you want a single file to share.
8. Take a screenshot of each page and save them in `screenshots\` (`powerbi_page1_executive.png` …).

**If something shows an error:** click the visual → read the message → see "Fixing problems" at the bottom.
This file was generated and checked by a script, but it was never opened in Power BI Desktop, so a small fix may be
needed. Fixing it is good practice, and a real story for interviews.

## WAY 2: Build it yourself from scratch (4–6 hours). This is how you learn

Think of it like cooking: **get ingredients (data) → prepare (Power Query) → organise the kitchen (model) →
recipes (DAX) → serve the plates (report pages).**

### Step 1: Load the data ("get ingredients")
**Home → Get data → Text/CSV** → pick `fact_sales.csv` → **Transform Data** (not Load).
Repeat for all 8 files: `fact_sales`, `fact_returns`, `dim_date`, `dim_customer`, `dim_product`, `dim_store`,
`dim_region`, `dim_channel`.

*Why "Transform" and not "Load"?* So you can check the data types before loading.

### Step 2: Check data types and names ("prepare")
In the Power Query window:
- Rename each query: `FactSales`, `FactReturns`, `DimDate`, `DimCustomer`, `DimProduct`, `DimStore`, `DimRegion`, `DimChannel`.
- Click the small icon left of each column header to set the type:
  - columns ending in `Key` → **Whole number**
  - money (NetSales, CostAmount, GrossProfit, RefundAmount, UnitPrice…) → **Fixed decimal number**
  - `Date`, `OpenDate`, `SignupDate`, `LaunchDate`, `FirstPurchaseDate` → **Date**
  - `OrderDateTime` → **Date/Time**
- **Close & Apply.**

*Why?* Wrong types are the #1 cause of wrong totals (e.g. money read as text can't be summed).

### Step 3: Build the model ("organise the kitchen")
Click the **Model view** icon (left side, 3rd icon).
1. Delete any lines Power BI drew automatically (right-click → Delete).
2. Drag **FactSales[DateKey]** onto **DimDate[DateKey]**. A line appears with `*` on the fact side and `1` on the
   dimension side. This is a **one-to-many** relationship.
3. Do the same for CustomerKey, ProductKey, StoreKey, ChannelKey, RegionKey (FactSales → each Dim).
4. Do the same from **FactReturns** to each Dim.
5. Drag **FactReturns[OrderDateKey]** onto **DimDate[DateKey]**. It becomes a **dotted** line (inactive). Correct!
6. Select DimDate → **Table tools → Mark as date table** → choose `Date`.
7. In DimDate, select `MonthShort` → **Column tools → Sort by column → MonthNumber** (so months go Jan→Dec, not A→Z).
   Same for `MonthName` → MonthNumber, `DayName` → DayOfWeekNumber, `YearMonth` → YearMonthKey.

*Why?* The model is the star schema: facts in the middle, dimensions around. Dimensions filter facts. Picking
"Electronics" filters the sales table.

### Step 4: Write the measures ("recipes")
Select the FactSales table → **Home → New measure** → paste one measure from `dax\measures.dax` → Enter. Start with these 10:

```DAX
Revenue = SUM ( FactSales[NetSales] )
Cost = SUM ( FactSales[CostAmount] )
Gross Profit = [Revenue] - [Cost]
Gross Margin % = DIVIDE ( [Gross Profit], [Revenue] )
Orders = DISTINCTCOUNT ( FactSales[OrderID] )
Average Order Value = DIVIDE ( [Revenue], [Orders] )
Customers = CALCULATE ( DISTINCTCOUNT ( FactSales[CustomerKey] ), DimCustomer[IsGuest] = "N" )
Revenue PY = CALCULATE ( [Revenue], SAMEPERIODLASTYEAR ( DimDate[Date] ) )
Revenue YoY % = DIVIDE ( [Revenue] - [Revenue PY], [Revenue PY] )
Refunds by Order Date = CALCULATE ( SUM ( FactReturns[RefundAmount] ), USERELATIONSHIP ( FactReturns[OrderDateKey], DimDate[DateKey] ) )
```
Format each one: click the measure → **Measure tools** → £ currency, or % with 1 decimal.

**Test immediately:** add a **Table** visual with `DimDate[Year]`, `Revenue`, `Gross Profit`, `Orders`. It must show
2024 £3,961,750 / 2025 £4,584,138. Don't continue until it matches.

### Step 5: Build Page 1, Executive Overview ("serve the first plate")
Click the report canvas, then for each visual click its icon in the **Visualizations** pane and drag the fields in:

| Visual | Where to drag |
| --- | --- |
| 7 × **Card** (top row) | Revenue · Gross Profit · Gross Margin % · Orders · Average Order Value · Customers · Return Rate % (Order Cohort) |
| **Line chart** | X-axis: DimDate[MonthShort] · Y-axis: Revenue · Legend: DimDate[Year] |
| **Table** | DimDate[Year], Revenue, Revenue YoY %, Gross Profit, Gross Margin % |
| **Clustered bar chart** | Y-axis: DimChannel[ChannelName] · X-axis: Revenue |
| **Clustered bar chart** | Y-axis: DimProduct[Category] · X-axis: Gross Margin % |
| 4 × **Slicer** (top right) | DimDate[Year] · DimRegion[RegionName] · DimChannel[ChannelName] · DimProduct[Category] |

Then: **Text box** for the title. Click a bar → watch the other visuals filter (cross-filtering).

### Step 6: Pages 2–5
Right-click the page tab → **Duplicate page** (keeps the title and slicers), rename it, delete the charts and build
the visuals listed in `01_build_guide.md` → Step 5. Use **View → Sync slicers** so the Year slicer works on every page.

### Step 7: Finish
- **View → Themes → Browse** → `northstar_theme.json`
- Add "Simulated data" to every page footer
- **File → Save** as `.pbix` · take screenshots for GitHub

## Fixing problems (common errors)

| You see | Why | Fix |
| --- | --- | --- |
| "Could not find file …" | `DataFolder` path wrong | Transform data → Edit parameters → fix the path, ending with `\` |
| Visuals empty | Data not loaded yet | Home → Refresh |
| Months in order Apr, Aug, Dec… | Sort-by not set | Select DimDate[MonthShort] → Sort by column → MonthNumber |
| YoY % blank | Date table not marked | DimDate → Mark as date table → Date |
| Totals much too high | Bi-directional or wrong relationship | Model view: every line single arrow, Dim → Fact |
| A visual shows "Something's wrong with fields" | A field name changed | Click the visual → re-drag the field from the Data pane |
| Return rate for the last month looks very low | Returns for December haven't happened yet | That's a real "return lag" effect. Explain it, don't fix it |

## What to say in the interview
"I loaded the cleaned star schema into Power BI, set data types, built one-to-many single-direction relationships
including an inactive one for the return order date, marked a date table, and wrote measures like margin, YoY and
return rate in DAX. Before building any visuals, I checked the totals matched my SQL. Then I designed 5 pages, one per
audience: executive, sales, profit, customers and returns."
